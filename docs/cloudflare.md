# Cloudflare: як програма потрапить у мережу

Програма — статичні файли (`dist/`), які віддає Cloudflare Workers (static assets), так само як сайт way1ong.eu й ігри. Налаштування — `wrangler.jsonc` у корені. Адреса — `https://sky.way1ong.eu` (рішення Дмитра 24.11).

Стан на 24.11.2026: у репозиторії все готово, але воркер у панелі **ще не створено** — це одноразовий крок Дмитра. Доки його не зроблено й запит на злиття не злито, за адресою нічого немає.

## Одноразове підключення (робить Дмитро в панелі Cloudflare)

Кроки ті самі, що 23.11 для ігор (`way1ong/games-puzzles`, `docs/cloudflare.md`); панель з того часу могла трохи змінитись.

1. Спершу злити запит на злиття в `main`: Cloudflare збирає `main`, а в порожньому `main` збирати нічого.
2. Cloudflare → **Workers & Pages** → **Create application** → **GitHub** → репозиторій `way1ong/way1ong-sky`. Якщо репозиторію немає в переліку — дати застосунку Cloudflare у GitHub доступ до нього.
3. На екрані «Set up your application»:
   - **Project name:** `way1ong-sky` — так само, як `name` у `wrangler.jsonc` (інакше збірка падає). Панель підставляє назву репозиторію; цього разу вона збігається, але перевірити.
   - **Build command:** `npm run build`.
   - **Deploy command:** `npx wrangler deploy` (типове значення).
   - **Preview command:** не чіпати. Гілка — `main`, тека — корінь репозиторію.
4. **Deploy.** Якщо з'явиться «Request failed with status 500» — натиснути ще раз (з іграми 23.11 спрацювало з другого разу).
5. Домен підключиться сам: у `wrangler.jsonc` записано `routes` з `sky.way1ong.eu`, а way1ong.eu уже в цьому акаунті Cloudflare. Перша викладка створить запис DNS і сертифікат. У панелі нічого натискати не треба.
6. Вкладка **Domains**: перемикачі **Production** (`….workers.dev`) і **Preview** лишити вимкненими — так записано й у `wrangler.jsonc`.

Після першої викладки сказати Claude: він запустить `npm run check:live` і звірить сторінку на справжній адресі зі збіркою.

## Що записано у `wrangler.jsonc` і чому

- `routes` з `"custom_domain": true` — адреса `sky.way1ong.eu`. Та сама адреса — у `src/config.ts`; тест `src/address.test.ts` стежить, щоб вони збігались.
- `"workers_dev": false` — без адреси `workers.dev`: у ній видно піддомен акаунта (рішення 24.11 для сайту й ігор).
- `"preview_urls": false` — без відкритих адрес для гілок: Cloudflare пише їх у запити на злиття.
- `"previews": {}` — без цього блоку перевірка на гілках падає (з'ясовано 23.11 на сайті).

Версію Node збірка бере з `.nvmrc` (та сама, що в сайту й ігор).

## Сторінки доходять без змін

На власному домені Cloudflare сам дописує до кожної сторінки скрипт свого Web Analytics (з'ясовано 23.11 на іграх) — це проти правил «без стеження» й «без зовнішніх запитів». `public/_headers` додає до кожного файлу `Cache-Control: … no-transform`: тоді Cloudflare не має права змінювати наші файли дорогою.

Перевірка на справжній адресі: `npm run build && npm run check:live` — запитує сторінку так, як браузер, і звіряє її байт у байт зі збіркою, а ще перевіряє, що маніфест, службовий скрипт і іконка на місці.

## Перевірити на телефоні після першої викладки

- Відкрити `sky.way1ong.eu`: політ, картка планети з фото, Місяць із позначками посадок, вільний політ.
- «Небо звідси»: вибрати місто, «Сьогодні», нічний режим.
- Android (Chrome, Samsung Internet): меню → «Встановити програму» → іконка з'явиться на екрані.
- iPhone: «Поділитися» → «На початковий екран».
- Вимкнути інтернет і відкрити програму з іконки — має відкритись і працювати, з фото в картках.

## Перевірено локально (24.11.2026)

- `npx wrangler deploy --dry-run` читає 41 файл із `dist/` (нічого не викладає).
- Збірку відкрито в браузері з локального сервера: службовий скрипт зберігає 37 файлів; без мережі програма відкривається, картки показують фото, вікна місій — знімки, небо працює.
- `npm run check:live` поки чесно каже, що адреса не відповідає: воркер ще не підключено.
- Не перевірено: справжня викладка, заголовок `no-transform` на справжній адресі, встановлення на справжньому телефоні.
